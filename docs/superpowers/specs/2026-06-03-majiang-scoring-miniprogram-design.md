# 麻将计分小程序 v2 设计文档

**日期**：2026-06-04（v2 重大重写）
**项目**：「胡了么」麻将记分小程序（基于微信云开发）
**状态**：待用户审阅
**作者**：通过头脑风暴流程与用户协作产出

> **v2 相对 v1 的核心转变**：
> - **品牌**：「麻记」→ **「胡了么」**
> - **核心交互**：从"按麻将规则选胡牌类型/番数/杠"改为 **"输家点赢家头像输入认输分数"** 的单向记账
> - **辅助功能**：保留"按玩法自动算分"作为番数计算器（用户手动确认应用）
> - **Tab 重组**：去掉"我的"和"帮助" Tab → 单页布局 + 房间内点自己头像改昵称 + 主页底部帮助按钮
> - **随机昵称**：麻将术语风（东风、南风、中发白...）
> - **房间内人数限制**：移除（任何人数都可以操作）

## 2. 数据模型

### 2.1 5 个集合

| 集合 | 用途 | 关键字段 |
|------|------|---------|
| **`rooms`** | 房间主表 | `_id, roomCode(6位), ownerId, status(active/finished), ruleId, playerIds[], createdAt` |
| **`players`** | 房间内玩家 | `_id, roomId, nickname, avatarIndex(0-7), seatIndex(0-3), isOwner, openid?, joinedAt` |
| **`rules`** | 房间计分规则 | `_id, roomId, baseScore, zimoMul, dianpaoMul, mingGangScore, anGangScore, bugangScore, maxFan(0=无限), maCount, dealerMul, allowDianpao` |
| **`rounds`** | 单局记录（含互相手动给分 + 辅助算分结果） | `_id, roomId, roundIndex, type(manual/auto), winnerId?, winType?, fan?, gangEvents?, scoreChanges{playerId: delta}, clientId, createdBy, createdAt` |
| **`users`** | 全局用户 | `_openid, nickname, avatarIndex, createdAt` |

**关键差异**：
- `rounds` 新增 `type` 字段区分手动（互相手动给分）和自动（辅助算分）
- `manual` 类型的 round 不需要 `winType/fan/gangEvents`，只存 `scoreChanges`（双向分数变化）
- `auto` 类型保持原有结构

### 2.2 互相手动给分的 rounds 记录示例

```js
{
  _id: '...',
  roomId: '...',
  roundIndex: 1,
  type: 'manual',           // 新增字段
  scoreChanges: {           // 双向记录
    'playerA_id': -5,      // 输家A -5
    'playerC_id': +5,      // 赢家C +5
  },
  clientId: 'cli_xxx',      // 防重复
  createdBy: 'playerA_id',  // 谁操作
  createdAt: 1234567890,
}
```

**幂等性**：`clientId` 由前端生成（`'manual_' + Date.now() + '_' + random`），保证同一操作不重复写入。

### 2.3 辅助算分的 rounds 记录

```js
{
  _id: '...',
  roomId: '...',
  roundIndex: 2,
  type: 'auto',
  winnerId: 'playerC_id',
  winType: 'zimo',
  fan: 1,
  gangEvents: [],
  scoreChanges: { 'playerA_id': -2, 'playerB_id': -2, 'playerC_id': 4, 'playerD_id': 0 },
  breakdown: {...},  // scoreService 计算结果
  clientId: 'auto_xxx',
  createdBy: '...',
  createdAt: 1234567890,
}
```

## 3. 核心交互流程

### 3.1 互相手动给分流程

1. 输家 B 在房间主页点"赢家 A"的头像
2. 弹窗「我给 [A 的昵称] 加 X 分」+ 数字输入框 + "确认"按钮
3. B 输入 "5" → 点"确认"
4. 前端：
   - 乐观更新：把临时 round 加入 `roomStore.rounds`
   - 调用云函数 `settleRound({ type: 'manual', scoreChanges: { B: -5, A: +5 } })`
5. 云函数 `settleRound`：
   - 入参校验（`type=manual` 时只需要 `scoreChanges` 和 `clientId`）
   - 验证 `scoreChanges` 守恒（代数和 = 0）
   - 分配 `roundIndex`
   - 写入 `rounds` 集合
6. 返回新 round → 替换临时 round
7. `db.watch` 推送给所有玩家 → 排行榜实时刷新
8. A 的总分 +5，B 的总分 -5

**关键设计**：
- 多个输家可同时点 A 输入（互不干扰）
- 同一输家可多次输入（5+3+2 = 输 10 分）

### 3.2 辅助算分流程

1. 任何人点"辅助算分"按钮 → 跳转到 `pages/room/auto-score/index`
2. 在该页面选择胡牌者、类型、番数、杠事件
3. 点击"计算" → 系统用 `scoreService.calculateRound` 算出 4 家的加减分
4. 显示"建议加减分"预览
5. 用户点"应用到房间" → 调用 `settleRound({ type: 'auto', winnerId, winType, fan, ... })`
6. 跳回房间主页 → 排行榜刷新

### 3.3 修改昵称流程

**位置 A：房间内**
- 点自己头像/名字 → 弹窗「修改昵称」→ 输入 → 确认
- 直接更新 `players.nickname`（在云端）和 `appStore.nickname`（本地）

**位置 B：首页**
- 点首页顶部的头像/昵称 → 弹窗「修改昵称」
- 更新 `appStore.nickname`（本地）
- 提示："去房间后才会同步给其他玩家"

## 5. 云函数变更

### 5.1 `settleRound` 扩展

接受 `type` 字段：
```js
// manual 模式（互相手动给分）
{ type: 'manual', scoreChanges: { playerA: -5, playerB: +5 }, clientId }

// auto 模式（辅助算分）
{ type: 'auto', winnerId, winType, fan, gangEvents, scoreChanges, breakdown, clientId }
```

**校验差异**：
- `manual`：只需 `scoreChanges` 守恒（代数和 = 0）+ 玩家存在性
- `auto`：原有完整校验（胡牌者存在、番数非负、玩家数 = 4 等）

**移除 `players.length !== 4` 限制**（v2 允许任意人数）。

### 5.2 `updatePlayer`（新增）

更新玩家昵称：
```js
{ roomId, playerId, nickname }
```

只有该玩家本人（通过 openid 或 clientId）可调用。

| 风险 | 缓解 |
|------|------|
| v1 → v2 大量 UI 改动 | 分阶段提交，每阶段可独立测试 |
